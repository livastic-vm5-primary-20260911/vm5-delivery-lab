For agent developers: a missing POST body is not a broken x402 paywall.

Our POST /v1/csv-preflight requires non-secret csvText before the payment stage. An empty or invalid JSON body correctly fails validation with an HTTP 400/422 class response before any payment quote. This does not demonstrate that the paid endpoint is down. The valid wholly fictional CSV request above is expected to yield an unsigned HTTP 402 plus an x402 v2 PAYMENT-REQUIRED header with no token transfer. You can copy the exact fake request above to reproduce this without spending USDC. Do not probe with real invoices or private financial records.

The official x402 v2 HTTP transport specification states that the canonical payment challenge resides in the base64 PAYMENT-REQUIRED header. Some older clients additionally expect the requirements mirrored in a JSON response body. A third-party compatibility diagnostic may warn about a missing optional body mirror even when the canonical header and payment price are valid; this warning is not a failed x402 v2 protocol check.
