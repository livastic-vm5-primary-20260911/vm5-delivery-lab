Explicit safety limits

It reports data issues. It never approves a payment.

What it really checks

Strict quoted CSV parsing; field count; nonzero 40-character hexadecimal EVM address shapes; case-insensitive duplicate recipients; positive, fixed-point Base USDC amounts in exact atomic units; explicit chain and canonical token column; formula-like data-cell prefixes.

Maximum 64 KiB, 500 rows, 8 columns.

What it never claims

Ownership or EIP-55 checksums; recipient verification, sanctions, chain state, allowances, token balances, fraud screening, gas simulation, legal compliance, contracts, actual transactions, payment finality or customer safety guarantees.

Never send cryptocurrency based only on a zero-error report.

This CLI accepts files from local disk or stdin and reports issue codes and row/column positions; it does not print source addresses, recipient notes or raw data cells. For private payroll, never commit the CSV or generated client information to a public GitHub repository. A cloud CI runner may still process files on that third-party provider; the CLI itself makes no network requests.

Before any crypto payment, check the real person's recipient address, correct chain (Base, 8453), canonical Circle USDC token (0x833589fCD6eDb6E08f4C7C32D4f71b54bdA02913), appropriate EIP-55 checksum verification, sanctions/KYC obligations where applicable, amounts and actual sender-wallet simulation using separately authorized tools.
